## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Owner feedback 2026-10-04 (see CS-104). Mechanical copy rules should be checked by a tool, not by memory: a lint over the files that hold user-visible text, and an inventory of every such file so the rewrite can run in parallel lanes without conflicts. The rules come from CS-104 (the first version can use the patterns already known: filler phrases, exclamation marks, Arabic letters, missing half-spaces, Latin digits in Persian text, a middle dot next to digits, repeated sentences, over-long strings) and are extended when the guide lands.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
DECISIONS (owner away, decided here).

SCOPE. A copy file is a file under apps/web/src with a string holding a Persian word (two Arabic-script letters in a row, not the U+0600 block: it also holds the Persian comma and the digits, which put 18 of 86 joiner-only files into the set), or one of the shared text modules listed in tools/copy-lint/copy-files.mjs (packages/search definitions and origin names, the three understanding-message modules, packages/notifications kinds, packages/locale unit words), or JSON under apps/web/public (the hero alt texts); a file that only joins values with the middle dot is a copy file for the dot rules. Excluded with a reason each: apps/worker, packages/ai, the understanding vocabulary, the /design and diagnostics pages, fixtures and test databases. A file with Persian text that is neither fails the lint, so new Persian text cannot hide. The TypeScript compiler API comes from apps/web (createRequire): no dependency, no lockfile change.

LEVELS (added once CS-104 had merged: appendix B of docs/design/product-voice.md is the source of the lint's list). Every rule declares a level, refuse or warn, and the loader refuses a rule without one. Refuse: a new or worse violation fails the lint, and existing ones sit in the baseline. Warn: listed with pnpm copy:lint --warnings (or by naming the rule with --rule), never fails, never baselined (--baseline-rule refuses a warn rule). The banned list (data/banned-phrases.mjs, 47 entries, each with level, group, why and instead) makes two rules: banned-phrase (17 refuse entries: appendix B's refuse words, the owner's brief, tells with no honest use) and discouraged-phrase (30 warn entries: appendix B's warn words and the section 7 patterns that need a reader). The refuse list applies to the superadmin section too, because the guide's own rewrites E93 to E96 take the database words and the word invalid out of admin text; the one entry exempt in area D is the warn entry superadmin-words (an entry's except takes globs or area:<id>). test/guide-alignment.test.mjs holds the lint and the guide together both ways: every word appendix B lists must be known and found at the level the appendix gives it, and a word added to the appendix later fails that test by name. Left to the reviewer because no cheap mechanical test exists: T11 ezafe chains, M4 triads, M12 machinery beyond the listed words, V1 two registers on one screen.

RULES (28 ids, 22 refuse and 6 warn, one module each under tools/copy-lint/rules; auto-loaded; the samples live in the module; test/rules.test.mjs fails a rule without a passing and a failing sample). Refuse: banned-phrase, exclamation-mark, arabic-letters, arabic-digits, half-space (also the prefix bi), latin-digits, middle-dot-digit, middle-dot-join, double-space, edge-space, repeated-sentence (five words or more, no holes, one file or one feature folder), english-word (data/allowed-latin.mjs: cc, km), straight-quotes, ascii-ellipsis, emoji, and seven length budgets by kind (button 3 words and 22 characters, label 4, name 10, title 8, hint 12, notice 25, popover 45; the guide says 40 for a popover, the lint refuses over 45 so a count by spaces never decides). Warn: discouraged-phrase, semicolon, long-sentence (over 25 words), parenthesis, repeated-phrase (eight words shared by two strings of one screen), range-hyphen. My additions to the task list: title and accessible-name budgets (an aria-label or alt is not a visible label); arabic-digits; middle-dot-join (a dot beside a value the file cannot see, for example a join with the middle dot: where the real violations are, because a static check never sees a digit next to those dots). Kind comes from the object key, the JSX attribute or the element (lib/kinds.mjs, documented in the runbook); a button, label or title that ends with a full stop is a notice. Exemptions: inline copy-lint-ignore with a reason (covers the next statement, property or element; malformed, unknown or unused ones are errors) and allowlist.json (a reason required, stale entries are errors).

BASELINE: tools/copy-lint/baseline/<area>.json, one file per rewrite area (A to E and CS-115), each (file, rule, count) with one entry per line, so five lanes lowering it edit five different files and cannot conflict; in .prettierignore; test/baseline-file.test.mjs fails if a file is not exactly what the tool writes, holds a file of another area or names a warn rule. pnpm check fails on a new violation or a worse count; --update-baseline only lowers (refuses and lists offenders otherwise); --baseline-rule <id> is the one way up, for a new or tightened refuse rule. Today: 140 violations in 80 entries (refuse rules only), made with --baseline-rule all after the last merge of main, because the lint reaches main with other lanes' copy already in it (CS-99, CS-103 and CS-111 added 4 files and 147 strings while this task ran); the 370 warnings are not recorded. AREAS: tools/copy-lint/areas.mjs (globs per area, overrides, notes); pnpm copy:inventory writes docs/design/copy-rewrite-plan.md and pnpm copy:inventory --strings <area> prints the strings of one area for a lane evidence table; test/areas.test.mjs fails when a copy file is in no area or two, or when a glob is dead.
