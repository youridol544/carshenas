## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The page where the product earns trust: why this price is a good or a bad deal, based on which cars, and whether the same car is cheaper elsewhere.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The price analysis draws the five deal bands as one continuous bar with a marker at this listing's price, the market value with its date and method, and an info control that explains the bands from the shared definitions; a listing with a market value but no rating shows the marker against the value with the reason and no band
- [ ] #2 The explanation is generated by code from stored facts through templates (no language model, so no credit and no invented number): a test proves every number in a rendered explanation comes from the database rows, and a labelled sample of 30 listings reports a faithfulness rate
- [ ] #3 Comparables (each linking to its own listing page), price history with days on market, condition chips with their source sentence, the seller's declared condition and risk flags are shown. The duplicate group (cheapest first) is not built: CS-55 and a second source do not exist, so the page has no placeholder for it
- [ ] #4 The primary action clicks out to the source listing, and on a phone it stays in reach
- [ ] #5 Playwright tests cover the page on phone and desktop (right-to-left, no sideways scroll, axe, the unrated reason, the re-check request), and it is added to e2e/fixtures/app-pages.ts
- [ ] #6 The main photo is the first listing_photo row, loaded from the source's own https address with no referrer and never through the optimizer or stored (ADR-0025); the other photos are a gallery; a photo that does not load shows the same-size placeholder
- [ ] #7 The page says when the listing was last checked; opening one whose last check is older than the freshness window records a re-check request (CS-35) and says so quietly, and a listing found gone says so plainly and offers similar listings
- [ ] #8 A missing listing answers a real HTTP 404, and a malformed percent-escape in the address answers a Farsi 404 instead of the framework's plain English 500, both proved in a browser test
- [ ] #9 Result cards on the search page lead to /listings/[id], and the page's data loader is one documented module that CS-65 and CS-67 reuse

From CS-28 (owner, 2026-09-27): Partial Prefetching is off so this page can answer a real 404. Read the id and the listing at the top of the page, with no loading.tsx and no Suspense around the page in any layout above it (either starts the stream), call notFound() before anything streams, and export instant = false: without it, next build fails with a blocking-prerender error (next-app-router.md; Next.js building guide). Keep the main photo and the title outside any Suspense boundary, so the photo morph from the results page forms in the navigation's commit; the results page prefetches its first screen of listings fully. Photos are our ArvanCloud copies (ADR-0010, CS-60).

From CS-30 (2026-09-28): /diagnostics/[failure], which reads params at the top with instant = false and no Suspense or loading.tsx above, was built as a partial prerender (◐) and answered 200 with noindex for notFound() and for a thrown error. The next-app-router rule's real-404 recipe did not give a 404 there; verify the listing page's 404 status in a browser test before relying on it (docs/learnings.md, 2026-09-28).

From CS-30 (2026-09-28): a malformed percent-escape in a dynamic segment (for example /listings/%E0%A4%A) fails inside Next.js 16.3.5 while it decodes the route params: a plain-text English 500, no onRequestError call, and only a warn request completed line in the log (measured on /diagnostics/[failure]). The listing page should answer such a path with a Farsi 400 or 404; the options are a proxy matched to the dynamic routes that refuses an undecodable path before routing, or a Next.js fix. docs/runbooks/logs-and-errors.md, Known limits.

2026-09-28 (ADR-0017 point 10): the page shows facts, our analysis and short quoted evidence for each condition fact, and clicks out to the source for the full listing. It never shows the seller's full description, contact details or photos beyond what CS-60 decides.
