# HOT updates of a sighting, and the expiry delete (CS-59, 2026-10-02)

24,996 synthetic listings (packages/search/scripts/seed-scale.ts), the final schema: a sighting moves only last_seen_at,
so no indexed column changes and the update can stay in its page (HOT). Every row of the table is updated in one
statement, three times in a row for each fill factor; `updated` is the rows changed by the pass, `hot` how many of them
were HOT updates. The table is rewritten (VACUUM FULL) between fill factors. The last block repeats it with an index on
last_seen_at, which is what an indexed expiry delete would need: no update is HOT, at any fill factor. (psql prints a
quoting error for the label of a pass; the numbers are unaffected.)

Expiry delete `DELETE FROM search_document WHERE last_seen_at < now() - 48 hours`, nothing to delete, run by search.refresh
every minute:
  without an index on last_seen_at: sequential scan, 4,705 buffers, 15.9 ms at 24,996 rows (about 4 ms at 6,000)
  with the index:                    index scan, 2 buffers, 0.35 ms
The decision (ADR-0028): no index, fill factor 80, so a sighting is a HOT update 26 % of the time on the first pass and 56 %
on the third (0.5 % at fill factor 100); revisit with the index when the delete passes 50 ms, about 80,000 rows.
