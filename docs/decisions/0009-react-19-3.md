# ADR-0009: Pin React 19.3.0 so unit tests run the React line the pages use

- Status: accepted
- Date: 2026-09-27 (decided by the owner on 2026-09-26)
- Deciders: Pedrum
- Related: supersedes the React version in ADR-0003; tasks CS-26, CS-27; `docs/research/2026-09-26-ui-craft-details.md`

## Context

ADR-0003 fixed `react` and `react-dom` at 19.2.8, as scaffolded. The App Router does not render with that package: Next.js 16.3.5 bundles its own React (`19.3.0-canary-cbb046ab-20260731`), while Vitest resolves the pinned one. With 19.2.8, unit tests had neither `<ViewTransition>` nor `addTransitionType`, which the craft rules use for the listing photo's shared-element morph (CS-26). React 19.3.0 has been the stable `latest` release since 2026-09-09, and the installed `@types/react` was already 19.3.

## Decision

Pin `react` and `react-dom` to 19.3.0 in `apps/web/package.json`, and the lint settings' React version to 19.3, so unit tests run the stable release of the 19.3 line whose canary the pages run. Everything else in ADR-0003 stands: the TypeScript and ESLint pins, the scaffold procedure, and each further dependency arriving with the task that needs it.

## Alternatives considered

- **Keep 19.2.8**: tests and pages would keep running different React minors, and `<ViewTransition>` could be covered only by browser tests.
- **Pin the canary that Next.js bundles**: matches the pages exactly, but canary builds change without notice and that version is an internal detail of Next.js.

## Consequences

- Positive: components that render `<ViewTransition>` can be unit-tested; the gap between test and page React narrows to stable against canary of the same minor.
- Negative / risks: the two still differ; when a React API behaves differently in tests and pages, compare `next/dist/compiled/react` with the pin (`docs/learnings.md`).
- Follow-ups: none. Verified in CS-27 with `pnpm check`, `pnpm e2e` and a Vitest render of `<ViewTransition>`.
