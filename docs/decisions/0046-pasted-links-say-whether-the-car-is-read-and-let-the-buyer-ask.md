# ADR-0046: A pasted link says whether Carshenas reads the car, and a buyer who wants it added asks with one action

- Status: accepted by delegation (the owner's standing instruction of 2026-10-03 and 2026-10-04; decided by the CS-115 lane on 2026-10-04)
- Date: 2026-10-04
- Deciders: Pedrum (delegated)
- Related: CS-115, CS-65, CS-71, CS-53, CS-50, CS-62; ADR-0034 (extended: its points 1 to 6 stand), ADR-0036, ADR-0037, ADR-0008, ADR-0017; `docs/design/data-model.md` ("Added by CS-115")

## Context

The owner's feedback of 2026-10-04: for a link of a car Carshenas does not read, the answer made the paste feature feel broken. It must state the limit, show what is read and let the buyer ask for the model. ADR-0034 answered a link from our own data and kept the links it had not seen as wanted, but a link for an ad nobody has read said only «not seen yet», for every car. The link carries more than its token: Divar's long form is `/v/<title with dashes>/<token>`, so the car can often be told from the title, with no request to Divar (the crawl is paused, and the pasted address is never fetched: no request, hence no SSRF). The catalogue has Persian names for only 12 of its 807 models, 114 of 161 makes, and the lane's index holds listings of ten models (the tracked ones) and two more.

## Decision

1. **Four answers, each in plain product voice, none that suggests a fault.** *Known* (the ad is in our data: its rating, as before; an ad that left the market says so). *Queued* (the car is read, this ad is not yet: it says what happens and, while nothing is being read, says that instead of a time; the best deals of the model meanwhile). *Outside* (the car is not read: the limit comes first, in the heading, naming the car; the short list of the cars that are read, as links to their pages; the one action, asking for the model). *Unreadable* (the link does not say which car: the short form has no title, the title names no car or two, or only a make some of whose models are read; what a full link looks like, with an example; another site is told only that Divar's ads are read for now). A slug that names no model is **unreadable, never unsupported**.
2. **The car is the listing's own model when we know the listing, else the one the catalogue's names read in the title**, by code (`packages/search`, `understand/title-car.ts`, on the plain-Farsi search's lexicon): a model's name anywhere in the title, longest first; digits glued to letters read apart; two names written together split (`دناپلاس`); the last three digits of a year (`صفر ۴۰۵`) are a year, not a Peugeot 405; what follows an exchange (`معاوضه`) or an engine (`موتور`) is another car; one or two Latin letters name nothing; a delivery order (`حواله`) names no car; two models, or a make that is not the model's own, are an ambiguity, never a guess. Measured on the 6,802 titles of the lane database whose pages were read, against the model Divar filed each under: the right model 83.7 %, a wrong model 0.2 % (accuracy 99.8 % where a model is named), only the make 11.7 %, nothing 4.0 %, ambiguous 0.4 %. A make none of whose models is read settles the question (outside, and the buyer picks the model among the make's); a make some of whose models are read does not (unreadable, naming the make and the read models).
3. **«Covered» is a model read in depth now:** a row of `tracked_model_scope` (state `tracking`) for the whole model. Decided from the data on 2026-10-04: exactly the ten tracked models had rated listings, so «tracked» and «rated» are one set. A paused model, or one tracked only through a trim, is not covered.
4. **Asking reuses CS-71's requests, through the buyer's own search file.** The requests of ADR-0036 hang on search files (demand is the files' distinct accounts; the decision reaches the buyer through the file), so the ask makes, in one transaction, the buyer's file for the model (or finds the one they keep for that exact search) and the model's request (found or made by its unique key), and links them. No new table or grant: the limits are the existing triggers (30 files an account, 10 requests waiting an account, 3 a file, none joining a declined request), mapped from their names, and a refused ask leaves nothing behind. The server action reads the car from the link again (the model never comes from the client alone; a chosen model is taken only for a link that names its make, and is checked against it), checks that the model is not read already and that the viewer has not asked, and rate-limits per account.
5. **A visitor is asked to sign in and comes back to the same answer with the request placed.** The answer explains why and links to sign-in and sign-up with the answer's address as `next`; the press is remembered in the tab's `sessionStorage` (never in the address or on the server) and placed once when the signed-in answer opens: a link someone else crafted places nothing, and a blocked storage only costs one more press. The answer then shows where the request stands (placed, accepted, declined with its reason) and never offers the action again; an approved request tracks the model (ADR-0037), so the same link then answers *queued* and says the model was added at the buyer's request.
6. **Demand is counted for links nobody has read.** `record_paste_request` takes the model the title names (migration `20261004072825`), so `model_demand` sees the cars buyers paste links of that Carshenas does not read; the superadmin's crawl-request screen shows, per model, the buyers, the requests and the links pasted in the last 30 days, and the models buyers only pasted links for.
7. **Honesty about time.** Nothing consumes `wanted_link` yet, so no copy promises that the pasted ad will be read first. The queued answer says ads of Tehran are usually read within hours (measured: in the steady state an ad is read within minutes of being first seen; the first backfill took 9 hours at the median), that reading is paused while it is (`readCrawlPaused`), and to paste the same link again afterwards.

## Alternatives considered

- **A request without a file** (a table that links a request to an account directly): it would change the demand count, the decision's notices, the inbox and the superadmin's screen, for no need the file does not meet; the file is also what alerts the buyer when the model's cars arrive (CS-72).
- **Place the request when a link with `?ask=1` opens**: a crafted link would place requests in a victim's name; the tab's own note is consent.
- **Treat a title that names no model as unsupported**: with names for 12 of 807 models, that would call most imported cars' links «unsupported» whatever the car is; only a make with no read model can say so.
- **A language model to read the title**: the evaluation of ADR-0029 shows code is more accurate on names; a link must be answered in a few milliseconds, with no spend and no key.
- **Fetch the ad once to read its car**: breaks the owner's pause and ADR-0034.

## Consequences

- Positive: a buyer knows at once whether the car is read, sees the cars that are, and has one action; the superadmin sees which cars buyers paste links of, with the buyers who asked; every number is from the database and no request leaves for any site.
- Negative / risks: 16 % of titles of a read car are not told (they name only the make, or nothing); a covered car's ad of another city is never read and the answer can only say that Tehran's are; the lexicon is kept for five minutes per process, so a model just added is named after at most that long; a visitor whose storage is blocked presses twice.
- Follow-ups: Persian names for more models (the catalogue's curated aliases) raise the share told; the crawler reading `wanted_link` first once the owner resumes it (CS-65's follow-up); withdrawing an ask (ADR-0036's follow-up).
