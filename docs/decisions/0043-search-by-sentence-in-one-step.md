# ADR-0043: Search by sentence in one step: a server action reads the sentence by code, the page goes to the canonical address with the sentence kept in it, and the words that would empty the results are left out

- Status: accepted by delegation (2026-10-04; the owner is away and asked that lane decisions be taken without him; the instruction to make the search one step is his, of 2026-10-04)
- Date: 2026-10-04
- Deciders: Pedrum (delegated to the CS-111 lane)
- Related: CS-111, CS-62, CS-63, CS-93, CS-114; ADR-0027, ADR-0028, ADR-0029; `docs/specs/S04-plain-farsi-search.md`, `docs/specs/S03-search-page.md`; `docs/evidence/query-understanding/2026-10-04/`

## Context

The first version of plain-Farsi search (CS-62, CS-93, CS-63) asked too much of the buyer: type a sentence, press «بفهم», read the understood chips, press «نمایش آگهی‌ها», and in the hero one more step; on the search page it also hid behind a disclosure. The owner (2026-10-04): the box «has to do it automatically: go to the search page and show the user what filters are applied from the sentence; no second click.» Code reads a sentence in about a millisecond (ADR-0029: 94.5 % fully right on the labelled set), so nothing the buyer does in between earns its cost. The model stays behind its default-off switch and its cost rules (ADR-0029 point 5), which is why it cannot be on the one-step path.

## Decision

1. **One box, one action.** The home hero's «جست‌وجو» tab and the search page's bar are one kind of form: a text box, one button, and example sentences under the hero's box that submit by themselves. There is no «understood» panel, no disclosure, no second button; the components of the first version are removed.
2. **The form's action is a Server Action, `askSearchAction`.** It reads the sentence by code in the server's process (`understandSentence` with the cached lexicon), settles the words no filter could name (point 4), and answers with the canonical address of the search with the sentence kept in one more parameter, `ask`: `/search?model=peugeot.206&trim=…&price=..700000000&nopaint=1&ask=<sentence>`. `ask` is page state, not part of the Search schema (ADR-0027): a search file stores the search and never the sentence, and every address the product builds from a Search is unchanged. Whatever else the box is given is looked after by the same action: a pasted listing link goes to its check, an empty box to every listing.
3. **The script navigates; the server redirects only when the script is not there.** A form sent before the script has loaded, or with none, is posted and the action redirects (303). The page's script calls the same action from a transition, marks the call (`by=script`), receives `{ status: 'found', href }` and navigates with `router.push`. The server's own `redirect()` was tried first and measured wrong: it is a navigation that does not keep the page it leaves (after Back the hero's box was empty, where a client navigation keeps the page hidden with its state) and it remounts the search page's tree (focus fell to the page's body after Enter). A client navigation leaves one history entry, keeps the home page's typed sentence for Back, and keeps focus in the box (on a touch screen the keyboard closes with the box and focus lands on the count of the results, which says what was found).
4. **Unread words are looked for in the text, and dropped when they would empty the results.** The words the understanding could not read (`unknown`, and a wish no filter serves) go in as the search's text `q`, shown as one quiet, removable chip. When that leaves nothing they are dropped one group at a time, the group whose going leaves the most listings first (the one written later on a tie), until something is found; the filters are never dropped (they are what the buyer asked for, shown as chips, each with what its removal would give in the no-results panel when they alone find nothing). A city outside the market, text addressed to the system and a number no car has are said and never looked for. At most four groups are counted. The page says what was left out and offers each word back. What was left out is derived whenever the page is drawn from the sentence in the address (code, milliseconds), never stored in it, so it stays true when the buyer takes a chip off or changes the filters: a group the page does not look for and that would leave nothing is said, and one the buyer took off themselves, which would find listings, is not.
5. **The sentence is the search, and stays editable.** A new sentence replaces the whole search (a hidden remainder of the old filters would make what the box says untrue). Chips, filters and order change the search at once and keep the sentence in the box; Enter reads it again; «پاک کردن فیلترها» clears chips, words and sentence; the box's clear button empties the box and lets go of the sentence.
6. **The model never waits, and never speaks when it is off.** Switch off (default): the action and the page use code alone, no request goes to the route, no line mentions a model. Switch on: the page is drawn from code at once and from a model's answer too when the layer's cache already holds one for the sentence (`cachedModelStep`: its gate refuses every request that would be paid, so drawing a page can never spend); when none is cached and the address is exactly what the code read and settled, a client leaf asks `POST /api/search/understand` in the background, once per sentence per tab, under one quiet line with its height reserved; the route's answer now carries `href` (the settled address), and the page replaces its own address when it differs, with no history entry. A buyer who changes anything meanwhile ends the leaf (the server stops drawing it) and a late answer is dropped.
7. **Failures are said, not thrown.** The server's failure and a request that never arrives come back as one message under the box, for that sentence only, with the sentence still in it; an unexpected error in the lines about the sentence is reported once and the page shows its results without them. One log line per sentence has counts and reasons, never the sentence.

## Alternatives considered

- **Keep the confirm step with a better label.** The owner's complaint is the step itself.
- **The server action redirects on every call** (the first implementation). One round trip fewer, but the page it leaves is not kept (the hero's sentence is lost for Back) and focus is lost on the search page; both measured on this build.
- **A route handler that redirects** (`GET /search/ask?…`). One more endpoint, the sentence in a request line, and no progressive-enhancement gain over the action.
- **The page reads `?ask=` alone and redirects itself.** In a streamed page a redirect is a meta refresh and an extra round trip; the address would pass through a state nobody asked for.
- **Fetch the existing `POST /api/search/understand`, then push.** No form behaviour before the script loads, and the route would have to do the settling too.
- **Apply the unread words as text and say «searching in text».** Leaves the buyer on an empty page with a sentence that sounds like a promise.
- **Drop filters automatically when nothing is found.** Hides what the buyer asked for; the panel's counted removals do it with their consent.
- **Record what was left out in the address.** Goes stale at the first chip taken off.
- **Keep the old filters when a new sentence is typed.** A hidden remainder; the sentence in the box would no longer describe the page.

## Consequences

- One step from the hero (type, Enter) and from the search page; Back brings the previous page with its box content; the address is the shareable canonical filter form plus `ask`, so a reload and a shared link show the same box and the same lines.
- The cost over a server redirect is one more round trip for a scripted submit (the action answers, then the page is fetched); the action itself takes a few milliseconds (the one log line has `durationMs`; measured on the lane's data, see the task notes). Prefetching `/search`'s shell makes the second request show the skeleton at once.
- The count queries (one to a handful per sentence with unread words, none otherwise, stopped at the first listing) are the existing search count with `countCap: 1`; no new SQL and no migration.
- Without scripts the search page itself shows nothing (Cache Components streams it into hidden elements that a script reveals; learned with CS-65), so the no-script path ends at the right address and the redirect, not at a drawn page; before the script has loaded the page is drawn and the form works.
- The short vague example in the hero («یک ماشین تمیز، کم‌کارکرد و بی‌دردسر») lands on its five filters, not on the catalogue «تمیز و بی‌دردسر»: the understanding's bundle needs the words about the technical condition, and its rules belong to the understanding (CS-99's lane touches them); to make the hero's example land on the catalogue the owner can ask for a phrase rule («بی‌دردسر» implies technically sound).
- Follow-ups for CS-114: suggestions while typing, recent searches, where the applied chips sit against the catalogue strip, and the wording of the lines about the sentence (the copy lanes rewrite them in `features/search/search-copy.ts` and `understanding-copy.ts`).
