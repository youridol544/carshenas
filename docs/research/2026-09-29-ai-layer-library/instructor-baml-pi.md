## instructor-js (`@instructor-ai/instructor` 1.7.0) with `llm-polyglot`

The repository is `567-labs/instructor-js` (npm still points to `instructor-ai/instructor-js`); llm-polyglot 3.0.0 lives in `hack-dance/island-ai` under `public-packages/llm-client`.

1. **Metis.** instructor-js only calls `client.chat.completions.create` (`src/instructor.ts@868ef8c1:166-173`), so any `new OpenAI({baseURL})` client reaches `/openai/v1` and `/deepseek/v1`. Its modes [source, `zod-stream@3.0.0` `src/oai/params.ts`]: `TOOLS` sends a forced function tool without `strict` (38-75); `JSON` sends `json_object` with the schema in a system message (139-161); `JSON_SCHEMA` sends `{type: "json_object", schema}`, the Together/Anyscale form rather than OpenAI's `json_schema` (163-187); `MD_JSON` puts the schema in the prompt only (77-98). No mode sends OpenAI's strict `json_schema`, Anthropic's `output_config.format` or Gemini's `responseJsonSchema`. The Anthropic provider in llm-polyglot calls `super({apiKey})` with no base URL (`island-ai@fe19f8b5 …/providers/anthropic/index.ts:41`), so only the process-wide `ANTHROPIC_BASE_URL` redirects it, and structured output there is a forced `tool_choice`. The Gemini provider passes no request options (`google/index.ts:115, 228`) and sits on `@google/generative-ai`, whose repository is archived ("This SDK is now deprecated"). **With zod 4.6.5 the model receives no schema** [probe]: `JSON_SCHEMA` sent `{"type":"json_object","schema":{}}` and `TOOLS` sent `"parameters":{}`, because zod-to-json-schema does not support v4 schemas ("While v3.25 supports Zod v4 as a peer-dependency, it does _not_ mean it supports v4 schemas", `zod-to-json-schema@3.25.2 README.md:386`), and that package has been deprecated since November 2025.
2. **Validation and re-ask.** zod only; `max_retries` defaults to 0 (`instructor.ts:28`). The re-ask resends the conversation, the last assistant JSON and `` `Please correct the function call; errors encountered:\n ${validationIssues}` `` (149-160), built from `fromZodError(...).message` (238); only a `ZodError` retries unless `retryAllErrors` is set (248); no retries when streaming (295-296). **With zod 4 the first validation failure crashes** with `TypeError: Cannot read properties of undefined (reading 'length')` [probe], because `zod-validation-error@3.5.4` reads `zodError.errors`, which zod 4's `ZodError` lacks; that is open issue #203 (2025-07-27), unanswered. With `zod/v3` schemas the error fails `instanceof ZodError` against zod 4 and is not retried; with `zod/v3` and `retryAllErrors: true` the re-ask works [probe: "…errors encountered:\n Validation error: Expected number, received string at "modelYear""].
3. **Streaming and tools.** `stream: true` yields partial objects through zod-stream; "tools" means only the forced response-model function.
4. **Usage.** `_meta.usage` is the provider's raw usage (204); no answering model (pull request #198, open), no request id, no cost; llm-polyglot's Anthropic provider keeps only prompt, completion and total tokens (`anthropic/index.ts:77-80`).
5. **OpenTelemetry and logging.** None. Error, warn and info messages always go to the console, even with a custom `logger` (93-117); a failed request printed `[Instructor:ERROR] … with params:` followed by the user message to stderr [probe] (181-187), which cannot be switched off.
6. **Test doubles.** Any object with `chat.completions.create` (485-496); a fake client worked [probe].
7. **Typed outcomes.** None: the parser reads tool arguments or `content` and ignores `finish_reason` and `refusal` (`zod-stream src/oai/parser.ts:82-109`); an empty or cut answer ends in a JSON `SyntaxError`; llm-polyglot collapses Anthropic stop reasons to `"tool_calls"` or `"stop"` (`anthropic/index.ts:114`). Nothing depends on log-probabilities.
8. **Registry, prompts, cache.** A `response_model` per call only.
9. **Maintenance and licence.** 802 stars, MIT, 14 open issues, last push 2025-01-27; releases v1.7.0 (2025-01-27), v1.6.0 (2025-01-14), v1.5.0 (2024-06-16); 0 commits since 2026-07-01; 36 contributors; 26,445 downloads a week; issues #201 and #203 unanswered, pull requests #198 and #202 unmerged. llm-polyglot: 162 stars, MIT, 6 contributors; 3.0.0 on 2026-07-10 after 2.6.0 on 2025-01-27; 7,773 downloads a week; its 3.0.0 changelog says its maintainers moved their own `evalz` "from Instructor and Chat Completions to native OpenAI 6 Responses structured outputs".
10. **Footprint.** 6 packages, about 111 kB, pure JavaScript; `zod-stream@3.0.0` declares peers `openai: 4.47.1` exactly and `zod ^3.23.3`, and npm raised peer warnings with openai 6 and zod 4 [probe].

**Verdict: poor.** Unmaintained, broken with zod 4, never uses the providers' native structured output, cannot reach Gemini through Metis, and prints prompts to the console.

## BAML v0 (`@boundaryml/baml` 0.226.2, 2026-09-01)

**Status.** The repository's README now describes a new "programming language for agents" (0.20.x nightlies); pull request #4297, merged 2026-07-31, brands the npm and PyPI line as "legacy releases" named "BAML v0". No end-of-support date for v0 was found (UNVERIFIED).

1. **Metis.** Every provider accepts `base_url` and `headers` [source; URLs and headers confirmed by probe]: `openai` → `https://api.metisai.ir/openai/v1/chat/completions` with Bearer (Responses is a separate `openai-responses` provider, `openai_client.rs:227-239`); `anthropic` → `https://api.metisai.ir/anthropic/v1/messages` with `x-api-key` and `anthropic-version: 2023-06-01` (`anthropic_client.rs:278, 294`, `clients/anthropic.rs:152-154`); `google-ai` → `https://api.metisai.ir/v1beta/models/{model}:generateContent` with `x-goog-api-key` (`googleai_client.rs:223-259`); DeepSeek through `openai` or `openai-generic` (not probed). **It never uses a provider's native structured output**: the body is the client's `options` plus the messages (`openai_client.rs:291-305`, `anthropic_client.rs:299`, `googleai_client.rs:261`), and the probed bodies carried "Answer in JSON using this schema" in the prompt and no `response_format`, `output_config` or `generationConfig` [probe]. The documentation says BAML "leverages Schema-Aligned Parsing (SAP) instead of … constrained generation or structured outputs" (`chain-of-thought.mdx:28`); issue #875, "Integrate directly with structured outputs", has been open since 2024-08-13, and a maintainer wrote on 2025-09-30, "we … have never managed to nail the abstractions we want to provide." Workarounds: a static `output_config.format` in the client options reached the Anthropic body unchanged [probe] but is not derived from the BAML type; or the modular API (`b.request` builds the request, we add the parameter and send it, `b.parse` parses the reply).
2. **Validation and re-ask.** Its own type system, no zod. The parser is very lenient: prose plus a code fence holding `{ make: "Peugeot", modelYear: "1399", fuel: "cng", }` became `{"make":"Peugeot","modelYear":1399,"fuel":"CNG"}` [probe]. `@assert` failures raise `BamlValidationError` (with `raw_output`, `prompt`, `detailed_message`); `@check` results come back as `Checked<T>`. `retry_policy` retries "requests that fail due to a network error" (`retry.mdx:6`), and the orchestrator stops at the first HTTP success whether parsing succeeds or not (`orchestrator/call.rs:107-126, 165-168, 181-183`): with `max_retries 2` and a failing `@assert`, one request and a `BamlValidationError`, no error fed back [probe].
3. **Streaming and tools.** `b.stream.Fn()` yields typed partial objects; tools are classes in a union return type parsed from the text (`tools.mdx:20`).
4. **Usage.** The Collector keeps `inputTokens`, `outputTokens` and `cachedInputTokens`; "Usage may not include … thinking_tokens or cache_creation_input_tokens" (`collector.mdx:776`), and the mock's cache-write and reasoning counts were dropped [probe]. The answering model and `x-request-id` are only in the raw HTTP response (null when streaming). No cost.
5. **OpenTelemetry and logging.** No OpenTelemetry (the runtime uses Rust `tracing`); Boundary Studio needs a vendor account and `BOUNDARY_API_KEY` (`studio.mdx:41`). **Prompts are logged by default** (`BAML_LOG=INFO`, `config.mdx:9`): every call printed a `---PROMPT---` block with the listing text and a `---LLM REPLY---` block [probe]; `BAML_LOG=OFF` silences it. The npm package depends on `@scarf/scarf`, which has an install-analytics `postinstall` (pnpm 10 does not run dependency scripts unless allowed).
6. **Test doubles.** `test` blocks and `baml-cli test` call the real model; no mock provider is documented. A localhost `base_url`, `b.request` snapshots and offline `b.parse` worked [probe].
7. **Typed outcomes** [probe]: an Anthropic refusal with empty content (HTTP 200) raised `BamlClientHttpError` ("…Anthropic response contains no text", `response_handler.rs:75`); a refusal with text raised `BamlValidationError`; **a reply cut at `max_tokens` (`{"make":"Peugeot","modelYear":1399,"fu`) succeeded as `{"make":"Peugeot","modelYear":1399,"fuel":null}`**, a silently truncated record, unless `finish_reason_allow_list ["end_turn"]` is set, which raises `BamlClientFinishReasonError`. Nothing depends on log-probabilities.
8. **Registry, prompts, cache.** Each task is a BAML function (typed inputs, prompt, client, return type) in `.baml` files; `ClientRegistry` swaps clients at run time; `b.request` gives the exact rendered request, which could be hashed for a cache key. No prompt version ids, no result cache.
9. **Maintenance and licence.** 9,355 stars, 368 open issues, pushed 2026-09-29, 109 contributors; the repository is Apache-2.0 while npm says MIT and ships the Apache-2.0 file. v0 releases 0.226.2 (2026-09-01), 0.226.1 (2026-08-19), 0.225.0 (2026-08-01), 0.224.0 (2026-07-31). Of 659 commits since 2026-07-01, 18 touch `engine/` (the v0 runtime) and 451 `baml_language/`. 254,671 downloads a week. Still 0.x; the generated client pins its version (`ThrowIfVersionMismatch`).
10. **Footprint.** 3 packages; the native binary alone is 55.5 MB on linux-x64-gnu. A code-generation step (`baml-cli generate`). **The generated client does not run under the worker's `--experimental-strip-types`**: its ESM output uses `export enum` and `.js` import paths, rejected with `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` and `ERR_MODULE_NOT_FOUND` [probe], so it needs a `tsc` build; the compiled JavaScript ran on Node 22.14. Next.js needs `serverExternalPackages: ['@boundaryml/baml']`, and `@boundaryml/baml-nextjs-plugin` 0.1.0 (2025-02-18) "does not yet support Turbopack"; Next.js 16 UNVERIFIED.

**Verdict: partial.** Prompts as typed functions, all four routes reachable, lenient parsing and typed errors; but no native schemas, no re-ask, silent truncation unless configured, prompts logged by default, thin usage, a native addon with a build step, and a "legacy" v0 line.

## pi-ai (`@earendil-works/pi-ai` 0.87.1, 2026-09-22)

The old name `@mariozechner/pi-ai` is deprecated at 0.73.1 ("please use @earendil-works/pi-ai instead going forward"); the repository is `earendil-works/pi`, package `packages/ai` (`badlogic/pi-mono` redirects there).

1. **Metis.** Each model carries its own `api`, `baseUrl`, `headers` and `compat`; `createProvider` registers custom ones. The built-in `openai` provider uses the Responses API (`providers/openai.ts:13`); a custom model with `api: "openai-completions"` uses Chat Completions. Anthropic calls `client.beta.messages.create`, which appends `?beta=true`, and may add `anthropic-beta` headers (`anthropic-messages.ts:588, 181-186, 1016-1031`). Probed requests went to `https://api.metisai.ir/openai/v1/chat/completions` (Bearer) and `https://api.metisai.ir/anthropic/v1/messages?beta=true` (`x-api-key`). Gemini: `api: "google-generative-ai"` with `baseUrl` `https://api.metisai.ir/v1beta` (`google-generative-ai.ts:352-365`), not verified on the wire because that adapter refuses a custom `fetch`. DeepSeek: compatibility is detected from "deepseek.com" or the provider id (`openai-completions.ts:1603`), so `compat` must be set for Metis. **It always streams** (`anthropic-messages.ts:1073`, `openai-completions.ts:819, 829`, Google `:100`); whether Metis streams on each route, and accepts `?beta=true`, is UNVERIFIED. **There is no structured output for a plain answer**: no `response_format`, `output_config.format` or `responseJsonSchema` in the source. The workarounds are a forced strict tool (`constrainedSampling: {type: 'json_schema', strict: 'require'}` with `toolChoice`; on the wire `"strict": true`, every property required, optionals nullable, `additionalProperties: false`, a forced `tool_choice` [probe]; custom models need `compat.supportsStrictMode` or `supportsStrictTools`, both off by default, `anthropic-messages.ts:216`) or replacing the payload in `onPayload` (`types.ts:148-152`), which put `response_format: {type: "json_schema", …}` on the wire [probe], leaving parsing and validation to us.
2. **Validation and re-ask.** Tool schemas are TypeBox or plain JSON Schema, so zod 4's `z.toJSONSchema` works. `validateToolArguments` (`utils/validation.ts:302-348`) clones, drops optional nulls, converts with `Value.Convert` and checks, throwing `Validation failed for tool "<name>":\n  - <path>: <message>\n\nReceived arguments:\n<json>` (347); with a zod-4-derived schema `"1399"` became 1399, and an invalid call gave `- modelYear: must be <= 1500` and `- fuel: must be equal to one of the allowed values` [probe]. Validation is manual (`toolcall_end` arguments are "complete, but not schema-validated"), with no automatic re-ask; the README suggests returning the error as a `toolResult` with `isError: true`. HTTP retries default to 0 (`provider-retry.ts:109`).
3. **Streaming and tools.** An event stream (start, text, thinking, toolcall, done, error) with partial tool-argument JSON; native tool calling on every adapter, with `toolChoice` and strict or grammar-constrained tools.
4. **Usage and cost.** `Usage` has `input`, `output`, `cacheRead`, `cacheWrite`, `cacheWrite1h?`, `reasoning?`, `totalTokens` and `cost` by part (`types.ts:396-417`); each message carries `responseModel`, `responseId` and `rawStopReason` (`types.ts:515-536`), and `onResponse` exposes headers, request id included. For 1,000 prompt tokens with 400 cached and 50 reasoning: input 600, cacheRead 400, reasoning 50, `responseModel` as answered, cost $0.00056 from custom prices, an Anthropic cache write priced too [probe]. Built-in prices are generated from `https://models.dev/api.json` and `https://openrouter.ai/api/v1/models` (`scripts/generate-models.ts:1289, 1753-1755`); a custom model takes its own `cost` per million tokens, with tiers (`models.ts:900-920`).
5. **OpenTelemetry.** No spans: a `telemetryContext` option (`types.ts:134`) is only passed through. `pi-telemetry` is a contract with no exporter, whose README says instrumentation "should avoid prompts, completions…" (389). The library writes nothing to the console outside its CLI and OAuth code.
6. **Test doubles.** `fauxProvider()` returns scripted replies and estimates usage ("No more faux responses queued" when empty) [probe]; `fetch` can be injected for the OpenAI and Anthropic adapters (`types.ts:141`), while the Google adapter throws "Custom fetch is not supported" (`google-generative-ai.ts:87-88`).
7. **Typed outcomes.** Stop reasons `stop`, `length`, `toolUse`, `error`, `aborted`, `pending`, `deferred`, with `rawStopReason` and `errorMessage`; an Anthropic `refusal` becomes `error` with "The model refused to complete the request" (`anthropic-messages.ts:1505-1509`), `max_tokens` becomes `length`, OpenAI `content_filter` and Gemini SAFETY become `error` [probe for the refusal; "Stream ended without finish_reason" for an empty stream]. Failures after the stream starts never throw (README line 936). Nothing depends on log-probabilities.
8. **Registry, prompts, cache.** A model and provider registry with prices and compatibility settings, and serialisable contexts; prompt versions, a result cache, schema validation for plain answers and a re-ask would be ours.
9. **Maintenance and licence.** 110,334 stars, MIT, 236 open issues, pushed 2026-09-29, 296 contributors; v0.87.1 (2026-09-22), v0.87.0, v0.86.1, v0.86.0 (2026-09-19), v0.85.1 (2026-09-05); 434 commits to `packages/ai` since 2026-07-01; 6,567,485 downloads a week plus 1,466,311 for the deprecated name. Still 0.x, and eight releases since 2026-07-01 carry a "Breaking Changes" section (0.80.7, 0.80.8, 0.82.0, 0.83.0, 0.84.0, 0.84.3, 0.85.0, 0.86.0; 0.86.0 changed provider stream inputs to `TranscriptContext`); renamed on 2026-05-07.
10. **Footprint.** 85 packages, 94 MB [probe], including the OpenAI, Anthropic, Google GenAI and AWS Bedrock SDKs whether used or not. ESM only; `engines` wants Node `>=22.19.0` (22.14 warns EBADENGINE; the probes ran). No native code, code generation, service or account. Next.js 16 UNVERIFIED.

**Verdict: partial, the best provider layer of the three.** It reaches every route natively with typed refusals and truncation, full usage and cost with custom prices, the answering model and test doubles; but it has no structured output for a plain answer and no re-ask, it always streams and adds `?beta=true` (Metis's support unverified), it breaks often, and it installs heavily.
